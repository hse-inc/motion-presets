# stagger（動きのプリセット）

作成: 2026-10-23

> 事例なしサンプル（基本セット）。子要素が 1 つずつ時間差で下から出そろう。

## 0. 分類
| 項目 | 値 |
|---|---|
| 名前 | stagger |
| ジャンル | 登場 |
| 質感 | フェード / スライド |
| 環境 | web |
| 出典 | 事例なし |
| 追加日 | 2026-10-23 |

## 1. いつ使うか
- 箇条書き・カードの列・メニュー・実績の数字など、同じ種類の要素が並ぶ塊
- 親に `.pf-stagger` と `.is-on`、子に `style="--c: 0"`（0 から順に）を付ける
- 子が多いと出そろうまで待たせる。出そろい＝ `--pf-delay` + `--pf-step` × (子の数 − 1) + `--pf-dur` を 2 秒以内に

## 2. どんな印象を与えるか
- 子要素が 1 つずつ時間差で下から出そろう。リストやカード列が「順に読める」リズムになる

## 3. パラメータ
> 土台の tokens.css に合わせて、案件側で推奨レンジ内に調整する。
| 変数名 | デフォルト | 推奨レンジ | 効き方 |
|---|---|---|---|
| `--pf-dur` | 500ms | 300〜700ms | 1 つが出る長さ |
| `--pf-step` | 100ms | 60〜200ms | 子と子の時間差 |
| `--pf-rise` | 24px | 12〜40px | 下からの移動量 |
| `--pf-delay` | 0ms | 0〜300ms | 最初の子が出るまでの待ち |

## 4. 使い方
1. `web/preset.css` を案件の CSS に取り込む（`tools/apply_preset.sh` で複製と `<link>` の追加ができる）
2. 親に `class="pf-stagger"`、子に `style="--c: 0"`（0 から順に）を付ける
3. 出したいときに `.is-on` を足す（swipe.js の出現処理がそのまま使える）
4. 案件に合わせて `--pf-*` を調整する（例: `style="--pf-dur: 500ms"`）
- 見本: `web/demo.html`

## 5. 注意
- reduced-motion: `prefers-reduced-motion: reduce` では動かさない指定を `web/preset.css` に入れてある。外さない
- AGENTS.md 2.8: 最初の動き出し 0.3 秒以内・1 ページの出そろい 2 秒以内。`--pf-delay` と `--pf-dur` を足して収まるようにする（待ちは `.is-on` 側にだけ書いてある）
